This multi-hour live-load verification **found and fixed 5 real bugs** the small-scale unit-test suite could never have caught (see DECISIONS.md D-013 through D-018): a full collector pipeline stall under real network latency (synchronous per-event Kafka publish), kafka-go's default 1s `BatchTimeout` silently throttling both the collector and the processor's stream/DLQ writers, a processor retry-deadline shorter than the vault's own configurable segment-seal window (would have silently dropped valid events in production), `Vault.Read` re-fetching+re-decompressing an entire segment on every single event read (fixed with a bounded LRU segment cache), and — the one that caused most of the confusion during this exact verification — `MaxSegmentAge` only being enforced reactively on the next write, so a segment that stopped receiving traffic sat unsealed indefinitely (fixed with a background seal-check ticker). Also found and fixed a real wiring gap: `vault.ulpf.raw_index`/`raw_segments` had fully-built, unit-tested writers that were never invoked by any running process — now fanned out from the collector's real publish path (`ulpfctl vault export-index` covers `raw_segments`). All five fixes have dedicated regression tests. |
